# LV999 下一步计划

## 当前决定

- 每个项目使用自己的 Notion Workspace 和普通页面留言板。Claude、Codex 在用户主动发起任务后通过 MCP 读取、追加；留言不自动触发 turn，Stop 后不自动恢复。
- 保留项目总览和 Workspace 入口。日常内容编辑继续使用 Notion，LV999 负责连接、映射、权限和迁移。
- 桌面使用自定义标题栏；主界面移除开发说明，诊断集中到 Settings。安全提示、错误和迁移差异继续展示。

## 下一步

1. 接入 LV999 和 AutoHoyo；建立项目首页、留言板与映射。将本计划放入 LV999 项目首页，验证重启后仍能读取。
2. 按项目发现 Vibecode 的页面、子页、Issues、Releases、视图、附件和引用。五个登记项目加公司狼单独形成清单；共享数据库按 Project 关系拆分，未知归属单列，不复制到所有空间。
3. 完成加密快照和逐项目 dry-run。先以小项目验证，展示源→目标、创建对象、关系映射、兼容字段及无法迁移项；批准具体 plan hash 后才复制。
4. 逐项目复制、重建关系并回读对账。源内容始终保留；公司狼包含整页研究、运行日志及项目子页，复制期间的新编辑必须识别。路由切换与源归档分别确认。
5. 完成迁移管理界面的真实清单、进度、暂停/恢复和报告；补齐托盘、单实例与独立干净 Windows 安装验收。未完成的能力不显示为已通过。

## 验收条件

- 连接的实际 Workspace 身份、授权页面和项目目标一致。
- 每个项目都有可通过 MCP 读写的普通留言板，自动 turn 数为零。
- 迁移逐项报告页数、记录数、附件、引用与差异；不能只以请求成功率或标题数量判定完成。
- Token、OAuth secret 和快照密钥不进入公开仓库、聊天、日志或普通配置。
