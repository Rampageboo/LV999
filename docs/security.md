# Current engineering security boundaries

- Only test workspace registrations are accepted; labels and live identities named Vibecode/Honour are blocked. A developer must explicitly assert `--test`; this does not magically identify every possible renamed production workspace.
- Tokens persist only in Windows Credential Manager. GUI enrollment necessarily uses transient input/IPC memory: the uncontrolled password field is cleared on submission, and cancel/escape discards it. Tokens are never React state, browser local/session storage, command-line arguments, real repository fixtures, environment configuration or SQLite fields. GUI/MCP cannot enumerate or retrieve stored credentials. The developer fallback prompt uses SecureString. The host does not enable WebView2 password autosave; its [documented default is false](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2settings.ispasswordautosaveenabled).
- Each content request resolves an exact registered ID, obtains only its credential and calls `/users/me`. Internal tokens must report that Workspace ID. OAuth credentials bind the token to the authoritative token-exchange Workspace/bot/owner evidence kept in the same vault entry; `/users/me` must match the authorized bot or owner, and any returned Workspace ID must match. An unavailable/mismatched identity blocks content access. No cross-space credential fallback exists.
- Browsing is explicitly scoped to one workspace and filters Notion title search to pages. Pagination is bounded per batch and cannot establish a complete inventory. Exact link inspection extracts only a validated page ID from supported Notion URLs; the server never fetches that URL. Only normalized metadata reaches the page browser, and all displayed content is escaped React text.
- Project keys are canonical and unique. Project names are normalized with NFKC/trim/lowercase for exact lookup; a non-unique name fails before credential reads. Saving/reassigning a route rechecks the selected workspace and retrieves the exact active ordinary page; database records are deliberately not eligible roots. No title-based or cross-workspace fallback exists. SQLite revision checks and a transaction with the success audit prevent stale edits or failed commits from replacing a mapping. A resolver also rejects a mapping changed during live validation.
- New GUI connections discover identity from the token and require a successful read-only search before persisting it. Duplicate identities require explicit reauthorization. Replacement must match the existing ID and pass the read probe before the old credential changes. Failed replacement validation leaves the current connection intact. Zero search results are explicitly a sharing/indexing warning.
- Vault writes are read back; SQLite registration/verification and its success audit commit in one local transaction. A caught save failure restores/deletes only the credential being changed, then checks the prior value. Failed compensation is reported as uncertain and clears positive proof. A per-workspace SQLite lease serializes these credential saves across instances sharing the registry; it expires after three minutes if its process crashes. This does not implement migration/job leases or guarantee atomicity across a process/OS crash between vault and SQLite operations. Developer scripts or external Credential Manager edits are outside this lease.
- Notion calls are centralized in the official SDK adapter with a fixed API version/base endpoint and disabled logger. Errors are mapped to fixed messages; untrusted API error bodies are discarded. Audit stores time, action, workspace ID, level and error code, not search text or page bodies. Route audit actions may include the validated ASCII project key. Page titles/IDs in saved route metadata remain private runtime configuration, not public fixtures.
- Management uses private parent/child pipes with allowlisted requests and a bounded host wait. The separate OAuth callback binds only IPv4 loopback port 8765 during an active authorization, expires after ten minutes and verifies exact Host/path/method and a random 256-bit one-use state. Codes are exchanged only against Notion's fixed token endpoint, with redirects disabled. The callback serves static text with no-store/no-referrer/CSP headers, never management operations, secrets or Notion content. An occupied port blocks authorization; LV999 never displaces its owner. The frontend has restrictive CSP and no generic shell/filesystem/network plugin. Its native browser opener accepts only the fixed Notion authorization endpoint/redirect and validated parameters.
- OAuth client secrets are separate per-client vault entries; access/refresh tokens and their identity evidence are saved as one atomic per-Workspace vault blob within WinCred's byte limit. SQLite retains only client ID and safe connection metadata. Reauthorization requires an explicit existing target and rejects another Workspace. Refresh is explicit and serialized by the connection lease; after remote renewal, uncertain local persistence requires reauthorization instead of pretending a potentially consumed refresh token was restored. Revocation/expiration produces a visible failure, never a fallback token or automatic grant retry.
- Client detection reads only known user-scope JSON/TOML files, returns status for the owned LV999 entry and never returns unrelated values. Existing configuration commands are not executed. Generated snippets contain runtime/data paths and optional group IDs, not Notion tokens. Native handshake probes create disposable profiles and working directories containing only LV999, so unrelated project MCP configuration is not loaded. No model turn, session resume or user-config write occurs.
- Local group messages persist privately in SQLite. Sender identity comes from the Owner-controlled stdio startup binding, never a tool argument; Workspace allowlists are checked before body reads and sends. This application boundary does not isolate hostile processes sharing the OS account or attest which native model consumed a response. Model-facing message bodies are untrusted and grant no added privileges.
- Message/recipient/success-audit/wake writes are transactional, retries are sender-key scoped, and changing a payload under a used key is rejected. Summaries do not update receipts; a full read API updates only the bound reader. Ordinary @ text is inert. Structured mentions queue only opted-in owned native sessions. A matching response nonce/message ID records native consumption and the fixed-actor reply atomically; no task Done is inferred. A manual acknowledgement requires a prior read, the target actor and group permission. Chat bodies are not copied into activity logs. Local chat access is independent of Notion authorization.
- Wake leases, per-binding ownership and generations prevent two dispatchers from sharing an active session or accepting a late stopped reply. Stop persists before interruption, and still interrupts its own local native process if persistence fails. Resume/Retry require current revisions; errors, quota/auth blocks and unknown expired outcomes pause instead of auto-retrying. Automatic handoffs are bounded by causal reply and hop count. Normal host exit pauses bindings and reaps owned processes; hostile OS-account access, abrupt OS termination and full supervisor/task recovery are not claimed solved.
- Native wake uses only LV999-created sessions in private message-only working directories. Claude safe mode disables customizations and tools. Codex disables configured MCP servers and relevant execution/app/plugin features, uses a read-only sandbox, and refuses every tool/approval request rather than approving it. Sign-in is reused through the native client; credentials are never copied. Existing native desktop chats are not controlled or synchronized. Native response receipts demonstrate a matched reply, not task correctness or cryptographic model attestation.
- Node is bundled, SHA-256 verified against the official distribution manifest and invoked by absolute path. Checksums downloaded from the same HTTPS origin protect against corruption; this is not an independent signature verification of Node. The host removes `NODE_OPTIONS` and `NODE_PATH` from the child environment.
- SQLite WAL and a busy timeout support local state concurrency. Wake/connection leases are implemented; migration-job leases, Notion write conflicts, migration approval, write idempotency and append-only content-write auditing remain future gates.
- The registry and timestamps are local user metadata. The local account can edit them; this is not an OS-user isolation or tamper-proof audit product. No remote access is supported in M0.

Do not interpret simulated adapter tests as real Notion acceptance. Previous native connection tests replaced Notion HTTP in an isolated app copy. The current wake/OAuth UI test runs the built frontend in isolated Chrome with a test-only IPC binding to a real management process; Notion/native bridge responses are scripted and generated credentials use the real vault, then are removed. It does not prove the changed Rust host. The production entry has no QA/adapter override. Real Codex turn/resume/Stop probes are separate. No real Notion credential was used. Current native packaging is blocked by Windows Smart App Control; the security policy was not changed or bypassed.
