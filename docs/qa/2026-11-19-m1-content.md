## Delivered behavior and limits

- Content writes require an explicit test Workspace policy and startup client write scope. Project writes require the current exact route revision and stay below its root; ambiguous project names fail before credential access.
- Content offers page/record selection, title search and pagination, child creation, text/property/block edits, local attachments, schema/query views and advanced typed operations. Plain-text block editing replaces that block's rich-text formatting. File uploads are bounded to 2 MiB; external file URLs are rejected.
- Trash, restore, block deletion and schema edits require Owner review of the exact request and resource version. Approval is stored server-side, expires, and is consumed once. The client receives only a non-secret plan reference; no approval credential is displayed.
- Each write keeps a retry key and records accepted object IDs before readback. Known accepted writes retry verification only. Unknown writes block new writes to that Workspace rather than silently duplicating content. Full reconciliation/recovery UI remains M2.
- A fresh version comparison detects observed edits, but Notion does not provide an atomic cross-editor compare-and-swap. Local leases cannot promise protection against an external Notion editor changing the resource after the last read.
- AI Clients can preview and apply only the LV999 entry, with byte-exact backup, stale-file rejection and preservation of unrelated settings. Unsupported inline TOML requires manual merge; it is never flattened or silently replaced. Close/reload the native client around application. No global client files were changed by acceptance tests.
- Native sessions default to message-only. Notion tools are opt-in and isolated to the bound Workspace; project write permission follows the actual message route. Ordinary messages never wake a model. Stop persists; Resume is an explicit Owner action and old messages require a separate Retry.
- Tray/background service, autostart, full crash recovery and migration execution remain later milestones. A separate clean Windows host with no preinstalled Node has not been tested; bundled-runtime checks on this host and Windows CI do not substitute for that M0/packaging environment gate.
